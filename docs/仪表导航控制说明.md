# 仪表导航接入规范（给实现方 AI 的任务书）

> **读者**：负责在本车机平台上接入仪表导航显示的开发者或 AI 编码代理。
>
> **目标**：让第三方导航应用把转向图标、路口距离、剩余里程/时间、道路名称
> 显示到原车仪表上，并在导航结束时正确清除。
>
> **本文是规范性文档**：标注「必须」的条目是硬性要求，标注「禁止」的条目
> 不得以"优化""兼容"为理由绕过。标注「未验证」的内容不得对外宣称可用。

---

## 1. 交付物

实现方必须交付：

1. 一个可在 **Android 4.4 / API 19** 上安装运行的 APK。
2. 一个集中封装协议的模块（建议单例或纯静态类），对外只暴露四个动作：
   `start()`、`update(icon, distanceMeters, ...)`、`stop()`、`release()`。
3. 一份字段映射说明：本项目自己的导航状态 → 本规范第 6 节的图标 ID。
4. 单元测试：覆盖第 10.1 节的断言清单。

`release()` 定义为幂等的 `stop()`：导航被取消、Activity 被销毁、
进程即将退出时都必须调用（见 8.3）。

---

## 2. 硬性边界（先读这一节）

### 2.1 必须

- **必须以普通应用权限运行**。本平台已确认：走第 4 节路径 A 不需要 root、
  不需要平台签名、不需要 `android.uid.system`。
- **必须只在车辆静止时进行首次联调**。
- **必须在退出导航时同时发送停止消息与结束状态**（见 8.3）。
- **必须对 `update()` 做节流**，不得无间隔循环刷写（建议最短间隔 500 ms，
  且仅在图标或距离实际变化时发送）。

### 2.2 禁止

- **禁止**声明 `android.uid.system` 或改用平台签名来"让调用成功"。本平台
  不需要，且会引入签名与升级风险。
- **禁止**直接操作 CAN 总线、串口、`/dev` 节点或 `mcu_server` 进程。
  只能通过第 4 / 5 节列出的接口。
- **禁止**发送本规范未列出的 `KEY_TYPE`、`EXTRA_STATE`、`navigation_id`
  或 MCU 命令号去"试探"。未知编码应先问，不要扫。
- **禁止**改动、替换、禁用原车 APK（`dualService`、`TSetServices`、
  `TMcuService2` 等），也不要自行启动/停止这些服务。
- **禁止**使用 `setNaviStatus2(...)`。该接口在本固件中是空实现，
  恒定返回 `-1`，不发送任何数据。
- **禁止**把"接口返回 0"当作"仪表已显示"（见第 9 节）。
- **禁止**把装箱的 `Integer` 传给 `putExtra(String, Object)` 重载。
  装箱值会走 `Serializable` 分支，原车用 `getIntExtra` 读取时拿到默认值，
  表现为"发出去了但没反应"。必须传 **基本类型 `int`**（见 4.4）。

## 4. 路径 A：通过广播接入（默认方案）

**适用**：只需要转向图标 + 距离 + 剩余里程/时间。
**状态**：已实车验证图标可显示。
**前提**：原车桥接服务在运行（见 4.5）。

### 4.1 消息序列（必须严格遵守）

```text
① start   导航开始
② turn    箭头 + 路口距离   （只更新缓存）
③ flush   触发提交           （把缓存送给 MCU）
④ stop    停止 + 结束
```

- ② 与 ③ **是两条不同消息**，必须成对出现。
- 只发 ② 不发 ③，仪表不会更新。
- 更换图标或距离后，**必须重新执行 ② → ③**。
- ③ 与 ② 之间不需要延时，但两者之间**没有完成回调**，不要假设有序确认。

### 4.2 字段表（键名、类型必须逐字一致）

| 步骤 | Action | 字段 | 类型 | 取值 |
| --- | --- | --- | --- | --- |
| ① | `AUTONAVI_STANDARD_BROADCAST_SEND` | `KEY_TYPE` | int | `10019` |
| | | `EXTRA_STATE` | int | `8`（开始），`10` 同为开始 |
| ② | `com.autonavi.navigation.NAVIGATION_UPDATES` | `navigation_id` | int | 见第 6 节 |
| | | `navigation_dis` | **String** | `"300,m"` / `"1.2,km"` |
| ③ | `AUTONAVI_STANDARD_BROADCAST_SEND` | `KEY_TYPE` | int | `10001` |
| | | `ROUTE_REMAIN_DIS` | int | 剩余总里程，单位**米** |
| | | `ROUTE_REMAIN_TIME` | int | 剩余时间，单位**秒** |
| | | `ROUTE_REMAIN_TIME_STRING` | String | 展示用文本，如 `"10 min"` |
| | | `ROUTE_ALL_DIS` | int | 全程里程，单位**米** |
| | | `CUR_ROAD_NAME` | String | 当前道路名 |
| | | `NEXT_ROAD_NAME` | String | 下一道路名 |
| | | `LIMITED_SPEED` | int | 限速 km/h，未知填 `0` |
| | | `ROAD_TYPE` | int | 道路类型，未知填 `0` |
| ④ | `com.autonavi.navigation.NAVIGATION_STOPPED` | 无 | — | — |
| ④ | `AUTONAVI_STANDARD_BROADCAST_SEND` | `KEY_TYPE` | int | `10019` |
| | | `EXTRA_STATE` | int | `9`（结束），`11`/`12` 同为结束 |

按需可选：

| 用途 | Action | 字段 | 值 |
| --- | --- | --- | --- |
| 退出导航 | `AUTONAVI_STANDARD_BROADCAST_SEND` | `KEY_TYPE` / `EXTRA_STATE` | `10019` / `2` |

### 4.3 距离字符串格式（硬性）

- 格式：`<数值>,<单位>`，**英文逗号**，单位仅 `m` 或 `km`。
- 合法：`"300,m"`、`"1.2,km"`、`"1500,m"`。
- 非法：`"300"`、`"300米"`、`"300 m"`、整数 `300`。
- `km` 会被原车换算为米（`1.2,km` → 1200）。
- 传入 `-1` 时，原车逻辑**直接返回、不提交**，仪表不会更新。
  因此"无有效距离"场景不得用 `-1` 代替，应跳过 ②③ 或使用第 6 节 ID `0`。

### 4.4 参考实现（可直接使用，但类型必须保持）

```java
static final String ACT_STANDARD = "AUTONAVI_STANDARD_BROADCAST_SEND";
static final String ACT_UPDATE   = "com.autonavi.navigation.NAVIGATION_UPDATES";
static final String ACT_STOPPED  = "com.autonavi.navigation.NAVIGATION_STOPPED";

static final int KEY_TYPE_STATE   = 10019;
static final int KEY_TYPE_SUMMARY = 10001;

void start(Context c) {
    Intent i = new Intent(ACT_STANDARD);
    i.putExtra("KEY_TYPE", KEY_TYPE_STATE);   // int
    i.putExtra("EXTRA_STATE", 8);             // int
    c.sendBroadcast(i);
}

void update(Context c, int gaodeIconId, int distanceMeters) {
    Intent i = new Intent(ACT_UPDATE);
    i.putExtra("navigation_id", gaodeIconId);              // int
    i.putExtra("navigation_dis", distanceMeters + ",m");   // String
    c.sendBroadcast(i);
}

void flush(Context c, int remainMeters, int remainSeconds, String remainText,
           int totalMeters, String currentRoad, String nextRoad) {
    Intent i = new Intent(ACT_STANDARD);
    i.putExtra("KEY_TYPE", KEY_TYPE_SUMMARY);
    i.putExtra("ROUTE_REMAIN_DIS", remainMeters);
    i.putExtra("ROUTE_REMAIN_TIME", remainSeconds);
    i.putExtra("ROUTE_REMAIN_TIME_STRING", remainText);
    i.putExtra("ROUTE_ALL_DIS", totalMeters);
    i.putExtra("CUR_ROAD_NAME", currentRoad);
    i.putExtra("NEXT_ROAD_NAME", nextRoad);
    i.putExtra("LIMITED_SPEED", 0);
    i.putExtra("ROAD_TYPE", 0);
    c.sendBroadcast(i);
}

void stop(Context c) {
    c.sendBroadcast(new Intent(ACT_STOPPED));      // 必须先发：清转向码
    Intent i = new Intent(ACT_STANDARD);
    i.putExtra("KEY_TYPE", KEY_TYPE_STATE);
    i.putExtra("EXTRA_STATE", 9);
    c.sendBroadcast(i);
}
```

### 4.5 依赖的运行态

路径 A 依赖两个**动态注册**的广播接收器：

| 组件 | 所在包 | 作用 |
| --- | --- | --- |
| 高德 `DualScreenService` | `com.chinatsp.dual.service` | 处理开始/结束，协调导航工作状态与显示请求 |
| `TDualService` | `com.chinatsp.tsetservices` | 缓存箭头/距离，收到 ③ 后提交 MCU |
| `TMcuService2` | `com.chinatsp.mcuservice2` | MCU 通信 |

- 「APK 已安装」不等于「服务在运行」。接收器是运行时注册的。
- 普通广播**不会**拉起这些服务。若服务未运行，本方案静默失效。
- 实现方**必须**提供"组件自检"入口，至少能报告这三个包的安装/启用状态，
  但不得声称"已安装＝可用"。

### 4.6 不要依赖路径 A 下发文字

③ 里的 `CUR_ROAD_NAME` / `NEXT_ROAD_NAME` **不会进入转向报文**。
原车服务只取距离、时间、箭头，另发一条
`com.incall.navigation.navi_current_status` 给其他消费者；
该广播是否被仪表采纳**未验证**。

> 需要确定地下发道路名称，必须使用第 5 节路径 B 的 `nextRoadName`。

## 5. 路径 B：直连 MCU 服务（需要文字/显示控制时使用）

**状态**：未实车验证。实现方必须先以路径 A 建立基线，再增量验证 B。

### 5.1 获取服务

```java
IBinder binder = (IBinder) Class.forName("android.os.ServiceManager")
        .getMethod("getService", String.class)
        .invoke(null, "mcu_service");
IMcuService service = IMcuService.Stub.asInterface(binder);
```

`IMcuService` 位于 `system/framework/framework2.jar`，包名
`com.chinatsp.mcumanager`。不引入该 jar 时按 5.6 手写 transact。

### 5.2 三个可用方法

| 方法 | 用途 | MCU 命令（cmd / smd） |
| --- | --- | --- |
| `setNaviStatus(int crossLength, int steer1, int steer2)` | 仅转向码 + 路口距离 | `0x0E / 0x0E` |
| `mpuNaviTInfo(int crossLength, int steer2, int steer1, int rateDistance, int retainTotalDistance, int retainTotalTime, String nextRoadName, int naviStatus)` | 完整导航包，**唯一含道路名** | `0x0E / 0x0D` |
| `mpuSysStateInfo(int playSource, int playStatus, int muteStatus, int huPhoneStatus, int tBoxPhoneStatus, int displayRequest, int naviWorkStatus, int displayThemeSet, int themeSwitchMusic)` | 显示请求 + 导航工作状态 | `0x0E / 0x02` |

**参数顺序陷阱（必须注意）**

```text
setNaviStatus(crossLength, steer1, steer2)       // steer1 在前
mpuNaviTInfo (crossLength, steer2, steer1, ...)  // steer2 在前 —— 与上者相反
```

写反会导致左右箭头互换。实现方必须在自己的包装层统一成
`(steer1, steer2)` 语义，并在调用 `mpuNaviTInfo` 时交换。

`mpuNaviTInfo` 的 `naviStatus` 与 `mpuSysStateInfo` 的 `naviWorkStatus`
不是同一字段，取值见 5.5。

### 5.3 `mpuNaviTInfo` 报文（77 字节，`0x4D`）

整数一律 **大端（高字节在前）**。

| 字节 | 长度 | 字段 | 约束 |
| --- | --- | --- | --- |
| 0–2 | 3 | `crossLength` | 上限 `0xFFFE` |
| 3 | 1 | `steer2` | 0–255 |
| 4 | 1 | `steer1` | 0–255 |
| 5 | 1 | `rateDistance` | 上限 `100`，超出按 100 |
| 6–8 | 3 | `retainTotalDistance` | 上限 `0xFFFFFE` |
| 9–10 | 2 | `retainTotalTime` | 上限 `0x7FFE` |
| 11–73 | 63 | `nextRoadName` | UTF-8，见第 7 节 |
| 74 | 1 | — | 实现方写 0 |
| 75 | 1 | `naviStatus` | 见 5.5 |
| 76 | 1 | — | 实现方写 0 |

**禁止传负数**：负数会被写成全 `0xFF`，仪表通常按无效值处理。
"无数据"应通过状态位表达，而不是填负数。

### 5.4 `setNaviStatus` 报文（5 字节）

| 字节 | 字段 |
| --- | --- |
| 0–1 | `crossLength`，大端 2 字节 |
| 2 | 固定 `0` |
| 3 | `steer1` |
| 4 | `steer2` |

### 5.5 `mpuSysStateInfo` 报文（8 字节）

| 字节 | 字段 | 说明 |
| --- | --- | --- |
| 0 | `playSource` | 媒体源 |
| 1 | `playStatus` | 播放状态 |
| 2 | `muteStatus` | 静音状态 |
| 3 | `huPhoneStatus` | 车机电话状态 |
| 4 | `tBoxPhoneStatus` | T-BOX 电话状态 |
| 5 | `displayRequest` | 显示请求，见下表 |
| 6 高 4 位 | `naviWorkStatus` | 导航工作状态 |
| 6 低 4 位 | `displayThemeSet` | 主题设置状态 |
| 7 | `themeSwitchMusic` | 主题联动音乐 |

`naviWorkStatus`：

| 值 | 枚举 | 含义 |
| --- | --- | --- |
| 0 | `NaviAppClosed` | 导航应用未启动 |
| 1 | `Cruising` | 巡航，未在导航 |
| **2** | **`NavigationalState`** | **导航中（进入导航显示用这个）** |
| 7 | `Invalid` | 无效 |

`displayRequest`（**枚举协议值 ≠ 报文字节，必须转换**）：

| 枚举 | 协议值 | 第 5 字节 |
| --- | --- | --- |
| `NoRequest` | 0 | `0x00` |
| `UnnormalDisplay` | 3 | `0x08` |
| `NormalDisplay` | 4 | `0x10` ← 导航显示 |
| `TelDisplayRequest` | 5 | `0x20` |
| `VRDisplayRequest` | 6 | `0x40` |
| `MediaDisplayRequest` | 7 | `0x80` |
| `MediaAndUnnormalNaviRequest` | `0x88` | `0x88` |
| `Invalid` | `0xFF` | `0x00` |

转换规则（原车实现）：值 `0` 或 `0xFF` → 字节 `0x00`；值 `0x88` →
字节 `0x88`；其余 → 字节 `1 << 值`。
直接调 Binder 却照抄协议值 `4`，会错发成 `0x04`。

### 5.6 不引入 jar 时的 transact 编号

```java
static final int TX_MPU_SYS_STATE_INFO = 0x5F;  // 95
static final int TX_MPU_NAVI_T_INFO    = 0x69;  // 105
static final int TX_SET_NAVI_STATUS    = 0x6A;  // 106
```

按 `Parcel` 顺序写入 `int` / `String`，再 `transact(code, data, reply, 0)`
并读回 `int`。**编号与固件版本绑定**，升级固件后必须重新核对，
不得"碰运气"试编号。

（`ClusterNaviIcons.SELECTABLE`）。

> 清除请用 ID `0`，或走 8.3 的结束流程。

### 6.4 图标使用规则

- 只使用上表 ID。未列出的 ID 一律视为不支持，**不得**自行编造或试扫。
- 右舵专用（`330`、`334~343`）与「未导航」占位（`344`、`348`）**不得**下发。
- 路径 A 更换图标后必须重发 `② → ③`。
- 路径 B 每次都必须重发完整报文（无增量更新概念）。

## 7. 文字（道路名称）要求

**仅路径 B 的 `nextRoadName` 可确定下发。**

| 项目 | 要求 |
| --- | --- |
| 编码 | **UTF-8** |
| 容量 | **63 字节**（报文第 11–73 字节） |
| 截断 | 按**完整字符**边界截断，禁止切断多字节字符 |
| 补齐 | 不足部分填 `0x00` |
| 空值 | `null` 按空字符串处理，整段填 0 |

容量换算：

| 内容 | 1 字节/字符 | 实际上限 |
| --- | --- | --- |
| 纯 ASCII | 是 | 63 字符 |
| 中文 | 否（3 字节） | 21 个汉字 |
| 中英混排 | 混合 | 约 20 个汉字 |

超长时原车实现会静默截断且不报错，因此实现方**应自行按字节预截断**
并保证不产生半个字符。

参考实现（必须保证字符边界）：

```java
static byte[] utf8Clamped(String text, int capacity) {
    byte[] out = new byte[capacity];                 // 默认全 0
    if (text == null || text.isEmpty()) return out;
    byte[] all = text.getBytes(StandardCharsets.UTF_8);
    if (all.length <= capacity) {
        System.arraycopy(all, 0, out, 0, all.length);
        return out;
    }
    int end = capacity;
    while (end > 0 && (all[end] & 0xC0) == 0x80) end--;  // 回退到字符起始
    System.arraycopy(all, 0, out, 0, end);
    return out;
}
```

注意 `all[end]` 的边界：`end == capacity` 且不足长度时已提前返回，
故此处不会越界。

## 8. 状态机（必须实现）

### 8.1 合法序列

```text
IDLE ──start()──► ACTIVE ──update()+flush()──► ACTIVE ──stop()──► IDLE
```

- 进入 `ACTIVE` 前必须先 `start()`。
- `ACTIVE` 期间允许重复 `update() + flush()`。
- 退出必须 `stop()`。

### 8.2 非法序列（必须被拦截，不得发送）

| 序列 | 处理 |
| --- | --- |
| 未 `start()` 就 `update()` | 直接忽略，并记录日志 |
| 只 `update()` 不 `flush()` | 视为无效，不得让上层以为已生效 |
| `stop()` 后继续 `update()` | 忽略，除非重新 `start()` |
| 重复 `stop()` | 允许，但应幂等，避免无意义刷写 |

### 8.3 结束流程（两条消息，缺一不可）

```text
1) com.autonavi.navigation.NAVIGATION_STOPPED     ← 清转向码并立即提交
2) AUTONAVI_STANDARD_BROADCAST_SEND
   KEY_TYPE=10019, EXTRA_STATE=9                  ← 结束状态
```

- **只发 2) 不会清除图标**。已在联调中复现：旧版仅发送结束状态时，
  仪表持续显示最后一次转向图标。
- 1) 沿用缓存中的距离，因此**必须先有过一次有效距离**，
  否则可能被原车的距离 `-1` 检查过滤。
- 两条消息由不同接收器处理，**不要假设完成顺序**，
  也**不要**在两者之间插入 ③。

路径 B 的结束：

```java
service.setNaviStatus(lastValidDistance, 0, 0);   // 转向码清零
// 视需要再将 naviWorkStatus 由 2 改回 1 (Cruising)
```

### 8.4 必须处理的异常场景

| 场景 | 要求 |
| --- | --- |
| 导航被取消 / 用户返回 | 必须调用 `stop()` |
| Activity 销毁 / 进程退出 | 必须在 `onDestroy()` / 退出前调用 `stop()` |
| GPS 丢失或数据过期 | 停止 `update()`，不得继续显示过期指令 |
| Binder 断开（路径 B） | 捕获 `DeadObjectException`，记录并重建连接 |
| 任务被系统回收 | 不得依赖后台常驻；恢复后重新 `start()` 并重发当前状态 |

## 9. 返回值语义（不得误用）

```text
接口返回 0
  ≠ 已发送
  ≠ MCU 已收到
  ≠ 仪表已显示
```

依据：

- 上层 `setSystemInfo()` 把消息投入工作线程后**立即返回 0**，不等待 MCU 回报。
- 底层检测到 `McuPowerMode = preSleep` 时会**直接丢弃发送，同样返回 0**。

可用的反馈源（路径 B）：

```java
InstrumentDisplayInfo info = McuManager.getInstance().getInstrumentDisplayInfo();
// 或注册 McuDataChangedListener → onInstrumentDisplayInfo(...)
```

可获得 `displayRequestStatus`、`displayNaviStatus`、`displayTheme` 等。
这些是**仪表上报的显示状态**，不是每条导航数据的确认。

实现方**必须**在 UI 上区分以下措辞，不得混用：

- 「已发送」：仅表示本应用调用了发送
- 「仪表已切换」：表示收到了仪表上报状态
- 不得使用「显示成功」

## 10. 验收标准

### 10.1 单元测试（必须可离线运行）

对报文构造层断言：

### 15.4 自动桥接（`ClusterNaviBridge`）

盒子下发的 `CMD 42 / 200` 导航数据可以直接翻译成仪表广播，不需要用户点按钮。
开关在调试页顶部，偏好键 `cluster_navi_auto`，默认**开启**。

#### 何时发什么

| 触发 | 发什么 |
| --- | --- |
| 内容变化且距上次 ≥ 1 s | **① → ② → ③**（① 每次重发，见下） |
| 有内容但还没有转向距离 | 只发 ①（先让仪表进入导航态） |
| `NaviStatus=0` 且 3 s 防抖后确认结束 | ④ 两条（`NAVIGATION_STOPPED` → `EXTRA_STATE=9`） |
| **盒子断开**（拔线 / USB 抖动 / 会话异常结束 / 换手机） | ④ 两条，不受开关控制 |

#### 四条硬约束

1. **每次都先补 ①**：车机仪表可能刚上电、刚重启，或在上一轮会话里掉线；错过
   最初那一次 ① 之后，即使 ②③ 一直发也不会显示任何图标。① 是幂等的状态设置，
   重复发没有副作用，所以每次下发都固定拼成 `① → ② → ③`。
2. **②③ 必须成对**（§4.1）：`onNavigationUpdate()` 永远同时产出 ② 和 ③，
   不存在"只发 ②"的代码路径。
3. **节流**：盒子约 0.5 s 一包，逐包转发会在车总线上刷屏。限制到
   `MIN_INTERVAL_MS = 1000`，且**内容没变就不发**（图标/距离/剩余里程/剩余时间/路名全同）。
   例外：状态机不在 ACTIVE 时必须发 —— 说明别处已经 ④ 收尾，下一包要重新用 ① 接上。
4. **转向距离未知时只发 ①**：`42/200` 是增量包，某些包只带 `NaviDistanceToDestination`。
   此时不能把 `-1` 钳成 `1` 米发出去（会显示"1m 左转"），要等真实值到了再补 ②③。

#### 图标映射：两套编号不是同一空间

盒子给的 `NaviOrderTypeNew` 是**手机导航的转向类型**（1~72，见 `Maneuver`），
仪表要的是原车映射表里的 **GAODE ID**（见第 6 节）。`ClusterNaviBridge.iconIdForOrderType()`
负责翻译，规则如下：

| `NaviOrderTypeNew` | 仪表 ID | 说明 |
| --- | --- | --- |
| 11~18 | 235 / 239 / … / 263 | 环岛第 1~8 出口，每档 +4 |
| 1、8 | 17 | 直行 / 直行变体 |
| 2 | 27 | 左转 |
| 3 | 22 | 右转 |
| 4、9 | 28 | 靠左 |
| 5、10 | 21 | 靠右 |
| 6 | 26 | 左后方 |
| 7 | 23 | 右后方（**不是**左转） |
| 19 | 25 | 左掉头（右舵用 24） |
| 20~22 | 21 | 匝道/出口按靠右驶出 |
| 31~39 | 27 | 左转分级，仪表无细分图形 |
| 40~51 | 22 | 右转分级 |
| 52~72、999、其余 | 17 | 不带方向，退回直行（**不猜左右**） |

> 单测 `testClusterNaviBridge()` 会把 `0..999` 全量跑一遍，断言**任何输入都
> 映射到表内、且可显示的图标**，不会产出右舵专用或「未导航」占位。

#### 与手工调试共用状态机

`ConnectionService.clusterNavi()` 是唯一的 `ClusterNavi` 实例，设置页通过
`MainActivity.clusterNavi()` 取同一份，自动桥接也用这份。因此在调试页手工点过 ①
之后，自动逻辑会直接续着发 ②③；自动逻辑已开始时，调试页按钮显示「导航中（可发 ②③）」。

| 事件 | 谁来收尾 |
| --- | --- |
| 盒子断开（拔线 / USB 抖动 / 会话异常 / 换手机） | `ConnectionService.clearNavigationState()` → `finishClusterNavi()` 发 ④ |
| `NaviStatus=0` 且 3 s 防抖过期 | `publishToCluster()` 发 ④ |
| Activity 销毁 | **不干预**（服务持有状态机，退出界面不等于导航结束） |

> 导致**每次退出界面都把仪表清掉**，而导航其实还在继续。现已改为只在本地兜底
> 实例上收尾。

| 项目 | 状态 |
